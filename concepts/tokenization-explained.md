# Tokenization 完全解释 — 为什么"我爱学习"变成了四个数字

> 这是 LLM 理解文字的第一步。不懂 tokenization，就看不懂价格、速度、上下文限制。

---

## 一句话

**模型不认识汉字，只认识数字。Tokenizer（分词器）就是把汉字翻译成数字的翻译官。**

---

## 为什么不能直接喂文字？

因为模型内部做的事只有一样：**矩阵乘法**。矩阵乘法只能处理数字。

```
"你好" → 模型无法处理（它不认识汉字）
[10899, 23147] → 模型可以处理（这是两个数字）
```

这和计算机不能"理解"文字是一个道理——计算机只理解 0 和 1。模型只理解向量（数字的数组）。

---

## Token 到底是什么

Token 是模型处理的最小单元。**不等于"字"**。

```
英文："Hello world" → 2 个 token：["Hello", " world"]
中文："你好世界"   → 4 个 token：["你", "好", "世", "界"]
```

### 为什么中文吃亏

英文一个单词通常就是 1 个 token（甚至带空格）。中文一个字通常是 1-2 个 token。

| 语言 | 同样意思 | token 数 | 比例 |
|------|---------|---------|------|
| 英文 | "I love AI" | 3 | 1x |
| 中文 | "我爱人工智能" | 5 | ~1.7x |
| 日文 | "私はAIを愛している" | 8 | ~2.7x |

> **实际影响：** 用中文调 API，同样的意思要多花 1.5-2 倍的 token → 多花 1.5-2 倍的钱。

---

## Tokenizer 是怎么分的

现代 LLM 用的都是 **BPE（Byte Pair Encoding，字节对编码）**。步骤很简单：

```
1. 先把所有文字拆成单个字符
2. 找出最常一起出现的两个字符 → 合并成一个新 token
3. 重复步骤 2，直到达到预设的 token 数量上限
```

举例（简化版）：

```
训练数据里经常出现：
  "学习" 出现 10000 次 → 合并成 token "学习"
  "习机" 出现 500 次   → 不合并（太少）
  "机器学习" 出现 8000 次 → 合并成 token "机器学习"
```

最终词汇表可能是：
```
["我", "爱", "学习", "机器", "机器学习", "AI", "!", ...]
```

模型拿到 `"我爱机器学习"`，分出来的可能是：
- `["我", "爱", "机器学习"]`（3 个 token）
- 而不是 `["我", "爱", "机器", "学习"]`（4 个 token）

因为 "机器学习" 作为一个整体出现得足够多，被合并了。

## 最常见的困惑

### "为什么同一个词有时被拆成不同的 token？"

```
"学习" 在句首：["学习"] → 1 个 token
"学习" 前面有空格："学习" → 可能被拆成 ["", "学习"] 或保持 ["学习"]
```

BPE 是有状态的——token 前后的字符会影响分词结果。

### "为什么 token 数量不等于字数？"

```
"今天天气很好" → 6 个字 → 但可能是 4 个 token：["今天", "天气", "很", "好"]
"I love you"   → 3 个词 → 3 个 token：["I", " love", " you"]
```

> 开头的 " love" 前面有个空格——这是英文 tokenization 的标准做法。空格被"吃进"了下一个 token 里，这样拼接时不需要额外加空格。

### "为什么有时候一个中文字拆成多个 token？"

```
生僻字 "龘" → 可能在 BPE 词汇表里没有，被拆成多个字节 → 多个 token
常见字 "我" → 肯定在词汇表里 → 1 个 token
```

BPE 的词汇表大小是固定的（如 50000、100000），装不下的就只能拆。

## 这跟你的钱包有什么关系

| 你做的事 | Token 消耗 | 省钱技巧 |
|---------|-----------|---------|
| 问一个简单问题 | ~20-50 token 输入 + ~100-300 token 输出 | 问题尽量精简 |
| 给一段 3000 字的文档让模型分析 | ~4000-6000 token 输入 | 先自己总结要点再提问 |
| 聊了 10 轮，每次都带历史 | 每轮输入都包含之前所有内容 → 指数增长 | 聊多了就 `/new` 重置 |
| 中文问 vs 英文问 | 中文多 1.5-2x token | 对 token 敏感的场合用英文 |
| DeepSeek 缓存命中 | 重复的 system prompt 不收费或半价 | system prompt 放最前面，不要变 |

试试这些：
- `"Hello world"` → 看英文怎么拆
- `"你好世界"` → 看中文怎么拆
- `"Hello 世界"` → 看中英混合怎么拆
- `"😀"` → 看 emoji 怎么拆（通常 1-3 个 token）
- `"  "`（两个空格）→ 空白字符也算 token

## 一句话总结

> Token 是计费单位，不是字数。中文比英文多 1.5-2 倍 token。生僻字比常见字多 token。Token 不能直接除以字数——去 OpenAI Tokenizer 页面自己试试就知道。
