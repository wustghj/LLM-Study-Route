# Prompt Engineering 速查手册 — 10 个即学即用的技巧

> 写 prompt 不是玄学。这 10 个技巧覆盖了 90% 的场景。

---

## 核心原则

**LLM 不会读心。你说的越清楚，它回答的越准。**

Prompt = 你给模型的指令。好的 prompt 包含三要素：
1. **角色**：告诉模型它是谁
2. **任务**：告诉它做什么
3. **约束**：告诉它怎么输出

---

## 技巧 1：角色设定

**给模型一个明确的身份，它的回答风格会完全不同。**

```
❌ 差："解释一下缓存"
✅ 好："你是一个教小学生电脑知识的老师。请用生活中的例子解释什么是缓存。"
✅ 好："你是一个资深后端工程师。请用技术语言解释 CPU Cache 的工作原理。"
```

**原理：** 模型在训练时见过大量"不同身份的人说话风格不同"的数据。设定了身份，它就会往那个方向输出。

---

## 技巧 2：Few-shot — 给它看例子

**给出 2-3 个"输入→期望输出"的例子，模型会模仿。**

```
请把以下句子翻译成机器能理解的逻辑表达式。

示例：
"如果明天下雨，我就不去" → IF(rain_tomorrow) THEN NOT(go_out)
"要是考试及格，妈妈就给我买Switch" → IF(exam_pass) THEN mom_buy(Switch)

现在翻译：
"只要有会员卡并且消费满 200，就打 8 折"
→ IF(has_member_card AND spend >= 200) THEN discount(0.8)
```

**原理：** 模型不需要"理解"你的任务——给它几个例子，它就找到了模式。

**适用场景：** 格式转换、风格模仿、分类任务、生成特定结构的内容。

---

## 技巧 3：Chain-of-Thought — 让它一步步想

**加上"请一步一步思考"，准确率飙升。**

```
❌ 差："我有 15 个苹果，给了小明 3 个，又买了 8 个，吃掉了 2 个。还剩多少？"

✅ 好："我有 15 个苹果，给了小明 3 个，又买了 8 个，吃掉了 2 个。
        请一步一步计算：
        第 1 步：初始苹果数
        第 2 步：给了小明之后
        第 3 步：买了之后
        第 4 步：吃掉之后
        第 5 步：给出最终答案"
```

**原理：** 模型是逐 token 生成的。让它"分步骤"，每一步的 token 都给下一步提供了正确的上下文。强制模型把推理过程"写出来"，减少跳步出错。

---

## 技巧 4：格式约束

**明确要求输出格式，减少废话和不确定性。**

```
❌ 差："分析一下这段代码"
✅ 好："分析以下代码。用 JSON 格式输出，包含三个字段：
        - bugs：潜在 bug 列表
        - performance：性能问题列表
        - suggestions：改进建议列表"

❌ 差："总结这篇文章"
✅ 好："用三句话总结以下文章。每句话不超过 20 个字。只输出总结，不要其他文字。"
```

**常用格式约束词：** "只输出 JSON"、"不要额外文字"、"用列表"、"用表格"、"不超过 X 字"。

---

## 技巧 5：说"不要什么"而不是只说"要什么"

**告诉模型正确答案的标准，也告诉它哪些是错的标准。**

```
❌ 差："写一篇产品介绍"
✅ 好："写一篇产品介绍。要求：
        - 不超过 200 字
        - 不要用"非常"、"极其"这种空洞的形容词
        - 每个功能给一个具体的数字或例子
        - 不要用套话开头（如'在当今时代'）"
```

---

## 技巧 6：System Prompt vs User Prompt

**System Prompt 设定全局规则。User Prompt 是具体问题。**

```
System Prompt（每次对话只设一次）：
"你是一个代码审查助手。对于用户提交的代码：
 1. 先指出安全问题（如果有）
 2. 再指出性能问题
 3. 最后给出改进建议
 用中文回答，每条不超过 2 行。不要闲聊。"

User Prompt（每次提问都不一样）：
"请审查以下代码：\n```python\ndef login(password):\n    if password == 'admin123':\n        return True\n```"
```

**关键技巧：** System Prompt 里的指令优先级高于 User Prompt。把最重要的约束放 System Prompt。

---

## 技巧 7：长文档处理——先问"找什么"，再调用

**不要直接把一万字文档扔给模型。先定位，再精读。**

```
❌ 差：扔进一篇 50 页的合同，然后问"这个合同有什么风险？"
        → 模型可能漏掉关键条款

✅ 好：
  第 1 轮："这份合同里，哪些条款涉及违约责任？只列出条款编号和标题。"
  第 2 轮："请详细分析第 7 条和第 12 条的风险，用通俗语言解释。"
```

**原理：** 把"查找"和"分析"分开。查找阶段模型只需要扫一遍，分析阶段集中火力在关键部分。节省 token，提高准确率。

---

## 技巧 8：让模型自己检查自己

**让模型先回答，再让模型评判自己的回答。**

```
第 1 轮："请解释什么是死锁。"
        → 模型输出解释

第 2 轮："请检查你刚才的解释：有没有技术错误？有没有遗漏重要概念？
         如果有问题，请给出修正版。"
        → 模型自我修正
```

**这招很管用**——模型在"审查"模式下的输出质量通常高于"生成"模式。

---

## 技巧 9：Temperature 的选择

| 场景 | 推荐 Temperature | 原因 |
|------|-----------------|------|
| 代码生成 | 0.1 - 0.3 | 代码需要确定，不能随机 |
| 事实问答 | 0.1 - 0.3 | 回答需要准确 |
| 翻译 | 0.3 - 0.5 | 略有灵活性 |
| 一般对话 | 0.6 - 0.8 | 平衡准确和自然 |
| 创意写作 | 0.8 - 1.0 | 要灵活性，不怕"跑偏" |
| 头脑风暴 | 0.9 - 1.2 | 要多样性 |

> Temperature 不是越高越好，也不是越低越好——看你的任务。

## 技巧 10：迭代——没有一次写对的 prompt

**写好 prompt 的方法和写代码一样：跑 → 看结果 → 改 → 再跑。**

```
第 1 版：跑一遍，发现输出太啰嗦 → 加"不超过 100 字"
第 2 版：跑一遍，发现输出格式不统一 → 加"每个要点一行，用 - 开头"
第 3 版：跑一遍，发现模型回答太泛 → 加"给出具体代码示例"
第 4 版：跑一遍，发现回答很好但漏了某类情况 → 加"也要考虑 X 场景"
```

**不要期望第一次就写对。prompt 是调出来的。**

## 速查：10 个技巧一句话总结

| # | 技巧 | 一句话 |
|---|------|--------|
| 1 | 角色设定 | 告诉模型它是谁 |
| 2 | Few-shot | 给它看 2-3 个例子 |
| 3 | Chain-of-Thought | 让它一步步想 |
| 4 | 格式约束 | 指定输出格式（JSON/列表/字数） |
| 5 | 负面约束 | 说清"不要什么" |
| 6 | System Prompt | 全局规则，优先级最高 |
| 7 | 分步处理 | 长文档先定位再精读 |
| 8 | 自我检查 | 让模型评审自己的回答 |
| 9 | Temperature | 代码/事实用低值，创意用高值 |
| 10 | 迭代 | 写→试→改→再试，没有一次写对的 |
