# 本地模型 Benchmark 记录 — 纯小白版

> 用数据代替感觉。每次跑完模型都记下来，积累自己的"性能档案"。

---

## 为什么做这个

同样的模型，在不同机器上跑，速度可以差几十倍。影响因素包括：
- 有没有 GPU、GPU 多强
- 模型大小和量化等级
- 上下文长短
- 模型是不是刚加载（冷启动 vs 热启动）

只靠"感觉很快"或"感觉慢"不够——你需要数字。

---

## 怎么测

### 方法 1：用项目自带的 benchmark 工具

```powershell
cd api调用实战/cli-chat
python benchmark.py --prompt medium --runs 3
```

它会自动跑 3 次取平均，输出 CSV 数据。用这个方式最省心。

### 方法 2：手动记录（用 CLI 客户端聊天时）

每次回答末尾都有 `[metrics] first_token_ms=xxx, total_ms=xxx`，把这两个数抄下来就行。

---

## 测试用 Prompt

固定一个 prompt，每次用同样的——这样对比才有意义。推荐用这个（中等长度，需要模型认真回答）：

```text
请解释什么是缓存（Cache），并说明为什么计算机系统需要缓存。
用生活中的例子类比，50-100 字即可。
```

> 不要用那个 C++ 后端风格的 prompt——你不是在测模型的 C++ 知识，你是在测延迟和吞吐。用通用问题就够。

---

## 什么叫"冷启动"和"热启动"？

| 状态 | 什么意思 | 首 token 延迟 |
|------|---------|-------------|
| **冷启动** | 模型还没加载到内存/显存，第一次请求 | 很慢（可能要等几秒甚至十几秒） |
| **热启动** | 模型已经在内存里了，第二次及以后的请求 | 正常速度 |

> 冷启动相当于"服务员还没上班，要先开门、开灯、准备食材"。热启动相当于"服务员已经在岗，直接点菜"。
>
> 所以你测第一个问题时首 token 会很慢——这不是 bug，是正常现象。从第二个问题开始计时才代表真实速度。

### 云 API vs 本地——关键维度对比

| 维度 | DeepSeek 云 API | Ollama 本地 |
|------|----------------|------------|
| **首 token 延迟** | 通常 200-800ms | 通常 2000-10000ms（取决于 GPU） |
| **token/s** | 通常 50-150 | 通常 10-50（有 GPU）/ 1-5（纯 CPU） |
| **成本** | 约 ¥1-2 / 百万 token | 电费（几乎忽略不计） |
| **隐私** | 数据发送到供应商服务器 | 数据不离开你的电脑 |
| **模型选择** | 供应商提供什么用什么 | 你能跑动什么用什么 |
| **运维** | 零运维 | 需要自己装、配、升级 |
| **断网可用** | 不能 | 能 |

## 进阶观察（学会了基础再回来看）

做完基础测试后，试试改变条件观察变化：

| 变什么 | 怎么变 | 预期看到什么 |
|--------|--------|------------|
| **上下文长度** | 连续聊 15 轮不 `/new` | total_ms 逐渐上升？ |
| **并发** | 开两个终端同时问 | 两个回答都变慢了吗？ |
| **不同量化** | 下载 Q2/Q4/Q8 三个版本分别测 | Q2 最快但质量差，Q8 最慢但质量好 |
| **系统负载** | 边打游戏边跑模型 | token/s 明显下降？ |
